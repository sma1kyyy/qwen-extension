## Коротко о главном

Проект — расширение для Qwen Code, которое генерирует React-интерфейсы на Plasma Web. После код-ревью и тестов выяснилось, что агент периодически "ломается": начинает галлюцинировать, генерирует битые компоненты, приходится по 3 раза перезапрашивать одну и ту же таблицу.

Разобрался и вот что нашёл и как фиксил

---

## Слой 1: Документация учила галлюцинациям

Самая жирная проблема, в документации были примеры, которые сами содержали то, что запрещено

### Что нашёл

**prompts.md** — "хороший" пример кода содержал:
```jsx
<Card padding="l" radius="l" shadow={true}>
```
А в той же папке SKILL.md написано: "у Card нет padding/radius/shadow". Агент читает оба файла и не понимает, кому верить. Начинает гадать и проигрывает

**README.md скилла** — минимальный пример:
```jsx
import { Button, HeadlineM, TextM } from '@salutejs/plasma-web'
<HeadlineM>Plasma Web</HeadlineM>
```
`HeadlineM` — компонент, которого не существует в природе. Он есть в таблице галлюцинаций этого же скилла. Агент его видит в примере, запоминает и потом генерирует страницы, которые падают в песочнице

**init-ui-project/SKILL.md** — базавый шаблон импортировал `HeadlineM` и ссылался на `generate-page`, который уже удалён

### Как решил

Прошёлся по всем примерам во всех документах и заменил:
- `HeadlineL/M/S` → `H1..H6` или `DsplL/M/S`
- `Badge tone="success"` → `Badge view="success"`
- `TextM tone="neutral"` → `TextM color="var(--text-secondary)"`
- `Button view="outline"` → `Button view="secondary"`
- `Button fullWidth` → `Button stretching="filled"`
- `Card padding/radius/shadow` → styled-обёртка `CardBody`
- `Avatar src="..."` → `Avatar url="..."`

Критерий: ни один jsx-блок в документации не должен содержать того, что запрещено в этой же документации. Проверил автоматическим скриптом

## Слой 2: Мёртвые ссылки на generate-page

Раньше было два скилла: `generate-page` (отвечал за сохранение файлов) и `plasma-web` (отвечал за генерацию UI). Потом их объединили в один `plasma-web`, а `generate-page` удалили

Но не везде подчистили хвосты:
- `prompts.md` — инструкция "передайте код в skill generate-page"
- `create-layout/SKILL.md` — description и примечание ссылались на `generate-page`
- `init-ui-project/SKILL.md` — структура проекта и инструкции

Поправил всё. Теперь сохранение страницы часть `plasma-web`, без вызова отдельного скилла

## Слой 3: MCP сервер падал по таймауту

MCP-сервер `@salutejs/sdds-mcp` запускается через `npx -y @salutejs/sdds-mcp@latest`. Первый запуск тянет пакет из npm то может занимать больше 30 секунд

В `qwen-extension.json` стоял `timeout: 30000`. Таймаут вылетал, MCP становился недоступен, агент падал на устаревшую документацию и начинались галлюцинации

Поднял до 60000 (60 секунд). Этого хватает с запасом даже на холодный старт

## Слой 4: Не было fallback-стратегии

Если MCP всё-таки недоступен (нет сети, npm registry лёг). Агент просто начинал импровизировать

Добавил в SKILL.md раздел "Fallback при сбое MCP":
1. Повторить вызов один раз
2. Если не помогло — работа строго по `docs/components.md`
3. Если компонента нет и в офлайн-доке — не использовать
4. Явно предупредить пользователя, что данные могут быть устаревшими

## Что в итоге получилось

### Что работает

- **Генерация страниц** — агент сначала дёргает MCP, проверяет компоненты, потом генерирует
- **Таблицы** — отдельная процедура с MCP-проверкой и чек-листом
- **Формы** — через Card + TextField + Checkbox + Button
- **Modal** — с open/onClose + useState
- **Layout** — через create-layout, потом инлайн в страницу
- **Сохранение в файл** — агент генерирует, спрашивает подтверждение, сохраняет
- **Fallback MCP** — если сервер упал, работа по офлайн-доку
- **Чек-листы** — перед генерацией агент проверяет: импорты, тему, экспорт, галлюцинации, props

### Что не работает (или не тестировалось)

- **`layouts/` пустая** — создавать layout надо через `create-layout`, сейчас там ничего нет
- **Инлайнинг layout'а в страницу** — SKILL.md говорит "возьмите styled-обёртки из layouts/", но если там пусто, возьмётся неоткуда. Надо сначала создать layout, но надо ли
- **MCP в офлайне** — если npm registry недоступен и пакет не кеширован, MCP не запустится. Fallback есть
- **Песочница** — я проверил валидность импортов и props, но физически не рендерил страницы в браузере. Если будешь тестировать  убедись что шрифты подключены

### Структура документации (чтобы не запутаться)

```
skills/plasma-web/
├── SKILL.md          — главная: цель, MCP, галлюцинации, каркас, процедура, чек-листы
├── README.md         — краткое описание скилла + минимальный пример
├── prompts.md        — системные инструкции для агента (role, rules, decision tree)
└── docs/
    ├── components.md — офлайн-справочник компонентов (MCP — истина)
    └── examples.md   — 13 эталонных примеров с кодом
```

Если что-то менять — править в первую очередь SKILL.md, он главный, остальные подчинённые
