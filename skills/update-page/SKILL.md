# update-page

Используйте этот skill для изменения существующих страниц: добавления/удаления блоков, замены данных, перекомпоновки секций, обновления стилей, исправления компонентов.

## Алгоритм работы

### Шаг 1: Получить список страниц

**Вариант A — через MCP (приоритет):**
Вызовите `mcp__ui-generator-mcp__search_project_pages` с именем для поиска. Если страниц много — предложите пользователю уточнить запрос.

**Вариант B — локально:**
Если MCP недоступен — проверьте папку `pages/` в корне проекта.

Покажите пользователю нумерованный список найденных страниц. Запросите, какую редактировать.

### Шаг 2: Получить текущий код страницы

**Через MCP:** вызовите `mcp__ui-generator-mcp__get_project_page` с ID страницы.

**Локально:** прочитайте файл `pages/<название>.jsx`.

### Шаг 3: Уточнить изменения

Покажите пользователю текущий код (или его структуру — заголовки, секции, основные компоненты). Спросите:

> «Что нужно изменить? Опишите изменения:
> — Добавить/убрать блок
> — Заменить данные
> — Поменять расположение секций
> — Обновить компоненты
> — Другое»

Если пользователь описания слишком абстрактное — задайте уточняющие вопросы. Не начинайте генерацию до полной ясности.

### Шаг 4: MCP-проверка компонентов (ОБЯЗАТЕЛЬНО)

Перед генерацией проверьте все новые/изменяемые компоненты через MCP `plasma-web`:

1. `list_components` — что компонент существует
2. `get_component_props` — какие props принимает

Если MCP недоступен — сообщите пользователю и ждите подтверждения.

### Шаг 5: Генерация обновлённого JSX

Сгенерируйте обновлённый файл, сохраняя:

- ту же структуру `export default function App() { ... }`
- ту же тему (`createGlobalStyle`)
- существующие компоненты без изменений, если пользователь их не запрашивал

Применяйте правила отступов и вёрстки из `generate-page` (spacing 4px, CardBody с padding 24px, etc.)

### Шаг 6: Публикация обновления

**Через MCP (приоритет):**
Вызовите `mcp__ui-generator-mcp__update_project_page` с ID страницы и новым JSX.

Верните пользователю ссылку на превью.

**Если MCP недоступен — локально:**
Спросите, сохранить ли изменения в `pages/<название>.jsx`. Только при явном «да» перезапишите файл.

## Основные сценарии изменений

### Добавление блока/секции
- Определите место (после какого блока, в начале/конце страницы)
- Проверьте новый компонент через MCP
- Добавьте с соблюдением отступов (marginTop: 16px между секциями внутри Card, 24px между Card на странице)

### Замена данных (текст, изображения, списки)
- Замените mock-данные, сохраняя структуру и типы

### Удаление блока
- Удалите JSX и связанные styled-components (если не используются больше)
- Проверьте, не осталось ли пустых контейнеров и лишних отступов

### Замена компонента
- Проверьте новый компонент через MCP
- Замените JSX с учётом разных props
- Удалите старый import, добавьте новый

### Изменение layout'а
- Если нужно сменить обёртку — запустите `list-layouts` для проверки доступных
- При добавлении layout — инлайньте styled-компоненты в страницу

## Жёсткие правила

1. **Экспорт:** только `export default function App() { ... }`
2. **Тема:** обязательна через `createGlobalStyle`
3. **Компоненты:** только из `@salutejs/plasma-web`
4. **Не смешивать UI-kit'ы**
5. **MCP-проверка** новых/изменённых компонентов обязательна
6. **Не менять то, что не просили** — сохраняйте существующий код без изменений
7. **После публикации** спросить: «Сохранить копию локально в pages/?»
